# 对话体验修复与外观设置

**状态：** 已实施并通过质量门（2026-11-13，分支 `feat/chat-ux`）。

**Goal:** 消除后台会话里凭空出现的「新会话 · 草稿」，让 Antigravity 的可重试服务错误不再把整轮标成失败并留下常驻红框，把回复里渲染层插入的 `[blocked]` 噪声去掉，把会话条数与对话区宽度做成设置页可改的产品设置。

**Tech Stack:** TypeScript、Zod、Zustand、React、Fastify、Vitest。

## Global Constraints

- 回复、注释、文档、提交信息一律中文。
- 会话条数默认 **5**，取值 1–20；对话宽度预设 **小 720 / 中 860 / 大 1040**，自定义 480–1400，默认「中」。
- 外观偏好写进 `packages/shared/src/settings/product-settings.ts` 的 `ProductSettingsSchema`，由现有产品设置存储与显式保存承载，不新建第二套存储。
- 不新增第三方依赖；不改 `apps/desktop` 打包配置；不升版本号。
- 测试不写死开发机绝对路径；不放宽既有超时来掩盖竞争。

## Review Focus

按最可能伤到真实使用者的顺序。除第 7 条外，均已由下表任务的测试覆盖。

1. 队列快照带的 `conversationId` 已不在内存（删除/归档会话、改项目目录、身份归并之后）→ 后台会话不得新增任何条目。
2. 队列仍有待发项但会话此刻空闲 → 后台入口必须仍能进入，不能因为改判定而丢掉真实待发队列。
3. 同一原生会话的内存视图被归并后，迟到的同 `sessionId` 快照 → 必须挂回存活视图，不得出现两条。
4. 磁盘上的旧 `product-settings.json` 没有 `appearance` 字段 → 必须读成默认 5 与「中」，不得报 `settings_invalid`。
5. ACP `session/prompt` 因 HTTP 524 失败但本轮已产出正文 → 不出现红色错误块，`turn_end.isError` 为 false；没有任何正文时仍必须报错并标记失败。
6. Antigravity 没有用量报告时，上下文面板的文案要说明是原生未报告，不能与「尚未开始」混为一谈。
7. 模型回复里的裸相对路径链接与自定义协议链接 → 不得显示成 `标签 [blocked]`；`http(s)`、`mailto:`、`#锚点` 仍要是可点链接；`javascript:`/`data:`/`file:` 必须继续保持不可点。

## 为什么（根因）

- **幽灵条目**：`applyFollowupSnapshot` 在内存里找不到 `conversationId` 时用 `emptyConversation` 伪造视图写进 `background`；该视图无 `sessionId`、无正文、无草稿，却因 `queueId` 被后台列表长期显示为「新会话 · 草稿」。全仓库只有 `emptyConversation` 会把 `queueId` 置回 `undefined`，一旦造出来就不会自行消失。触发点是文档重建（刷新、Vite 整页 reload）后服务端无条件重放旧队列快照，其中 `conversationId` 属于上一个文档。
- **报错粘在每条回复上**：不是「旧错误没清掉」，而是每轮都被判成失败。ACP 把含 524 的 JSON-RPC 错误映射成致命 `AcpError('native')` 并直接发 `error` + `turn_end.isError = true`；headless 通道把 stderr 里的 524 立即发成永久错误并置位 `nativeFailure`，使 `naturalSuccess` 永远为假。agy 网关在长回复末尾返回 524 是常态，正文其实已经流完。
- **上下文用量空态**：文案对所有 CLI 一律说「此会话尚无可用的上下文用量与窗口报告」，看不出是原生没报，还是应用没接。
- **回复里的 `[blocked]`**：不是模型输出，也不是原生协议字段。`rehype-harden`（Streamdown 默认 rehype 插件，`defaultOrigin: undefined`）遇到 `new URL()` 解析不了的链接会替换成 `<span>` 并在文字后插入文本 `" [blocked]"`。实测被追加的目标：仓库内文件引用（如 `src/app.ts`、`docs/readme.md`、`package.json`）、自定义协议（`vscode://…`）、Windows 盘符路径、大写协议；不受影响的有 `https:`、`mailto:`、`tel:`、`irc:`、`xmpp:`、`#锚点`、`./x`、`../x`、`/x`、`//host/x`。agy 回复里大量出现仓库内文件引用，于是每条回复都带出标记。安全策略要保留（`javascript:`/`data:`/`file:` 必须继续拦），错的是「正常但不可解析」的链接被降级成噪声。

## 怎么做（已确认）

| 点 | 决定 |
| --- | --- |
| 幽灵条目 | 快照只挂到已存在的视图（先按 `conversationId`，再按原生 `sessionId` 认领），都没有就丢弃；后台列表从「有 queueId」改为「队列仍有未完成项」 |
| 报错 | 服务型诊断（500/503/524）不再等同于本轮失败：headless 先暂存、确认失败才上报；ACP 仅在「已产出正文 + 可重试 + 未中断」时降级为可折叠记录并把 `turn_end` 记为成功 |
| 报错兜底 | 时间线里的错误条目可手动关闭 |
| 上下文文案 | 按 CLI 区分，Antigravity 说明是原生未报告 |
| 回复里的 `[blocked]` | 在 Markdown 解析阶段把不可渲染的链接降级为纯文本，不放宽安全策略 |
| 条数 | 默认 5，可调 1–20，放在设置页「通用设置」 |
| 宽度 | 小/中/大/自定义，共用 `--conversation-width` 变量，放在设置页「通用设置」 |
| 存储 | 两项都进服务端产品设置（新增 `appearance` 段） |

## 非目标

- 不重做时间线的流式渲染：现有的 delta → `Streamdown` 流式路径正常，本次不动。
- 不改侧栏拖拽宽度等本机界面偏好（仍在 localStorage）。
- 不为旧数据集写迁移脚本，`appearance` 缺失由 Zod 默认值补齐。
- 不改服务端的重放策略：客户端不再信任未知快照已足够，避免动重连语义。

每个任务都先写失败测试、确认红灯落在待修行为上，再实现、提交。

| 任务 | 改动 | 关键测试 |
| --- | --- | --- |

### 执行中的更正

- 最初把「报错粘在下一条消息」判为「错误条目没清除」，实际是每轮都被判成失败（`turn_end.isError` 一直为真）。按后者修复后，正常轮次不再产生错误条目，关闭按钮只作为兜底。
- 按「可重试错误降级」而非「按轮次折叠历史错误」实现：后者要引入错误归属标识，成本高且与「原生历史里本就没有错误条目」的事实不符。
- `[blocked]` 处理第一版把断言写成查找 `<a>`，实测 Streamdown 把可点链接渲染成 `<button data-streamdown="link">`，断言随即修正。
- 侧栏开始读产品设置后，一个既有用例因多个请求复用同一 `Response` 实例（body 只能读一次）而失败，改为按端点返回新实例，并只统计会话操作请求。
