# 原生 CLI 对话接入

本文记录三 CLI 的对话协议与运行方式。验证结果见[路线图](../roadmap.md)，旧设计与早期验收见 `c686ef2:docs/engineering/native-dialogue.md`。

## 1. 会话归属

按项目打开原生会话，在同一条记录上继续工作。对话正文由 CLI 保存；界面与传输只持有运行和恢复所需的内存状态。

## 2. 当前接入

- 在已有项目中选择三个 CLI，显式发送才新建会话；点击列表中的原生会话可以继续。
- Claude/Codex 展示历史、流式文本和工具事件，接住原生决定发出的审批，支持停止。
- Antigravity 读取摘要与目录归属，并通过原生服务回放已适配的文本、工具与活动步骤。新回合仍使用原生 id 续接，不把界面内容复制成另一个会话库。
- Antigravity ACP 承接原生权限请求；兼容 headless 路径在实际发生软拒时显示说明，不伪造允许按钮、不默认绕过权限。
- 模型和强度默认留空，表示继承 CLI；AGY 自定义窗口的临时标签启动会保留经原生目录确认的变体默认档位。模型候选来自本机能力目录，用户也可手填标识；强度优先采用原生报告，未报告时按[已核对的精确型号](model-capabilities.md#已核对的精确规则)补全。
- Claude、AGY 和非 ChatGPT 模式的 Codex 模型目录可跨应用重启复用；首次无缓存时打开菜单获取，也可手动重新获取。技能与命令不写入模型缓存，显式打开技能入口后按实际目录获取；原生技能的斜杠补全只读取已有目录。
- AGY 和 Codex 的账号模式支持按需查看原生额度，获取条件与字段见[原生配置](native-configuration.md#启动环境)。
- Claude 的探测与实际驱动采用同一份本机程序；找不到时明确失败，不回退到 SDK 自带程序。SDK 仅作为协议客户端。
- 对话与执行轨迹共用事件归并；原生用量、步骤耗时和上下文进入统一展示，平均速度按回合或步骤分别计算。完整字段及计量边界见[CLI 用量与执行轨迹](cli-observability.md)。

## 3. 运行边界

### Antigravity ACP 与 headless 选择

AgentDeck 通过本机 `agy acp` 执行符合条件的 Gemini API Key 会话，以及个人 Google 登录会话中带图片的回合。账号发图沿用原生缓存凭据和 AGY 代理，认证环境与闲置的 Gemini API Key 及 ADC 隔离；要求本机已有可确认的登录身份。账号的纯文字与只带文件的回合走 headless。

发图前核对原生会话 ID、实际工作目录及模型参数；旧会话用 `session/resume`，不重新投递历史。ACP 续接会重新报告模型、强度与模式，不能视作上一轮选择已沿用；按当前选项重新核对明确选择和原生配置默认，官方型号变体见[模型能力](model-capabilities.md#已核对的精确规则)。遇到不支持的设置或续接失败时保留输入，不改用默认模型、不丢图改发文字。AGY 自动权限模式仍可发文字，本接入不为发图自动切换权限。

Gemini API Key 的自定义模型、ADC 和不兼容的设置沿用原有 headless 选路；以前可回退的兼容情况也只在输入尚未投递时回退。已投递的消息，包括已经产生部分回复但失败的账号图片回合，不切换协议重发。原生权限请求按原生选项 ID 返回本次批准或拒绝，取消使全部未完成批准失效。

ACP 的本轮结束依据 prompt 结果与运行状态确认，明确的服务错误映射为脱敏诊断。公开文本、思考、工具和计划进入时间线，媒体、提问和引导按[能力矩阵](native-capability-matrix.md)开放；headless 的续接错误归属复核只用于 headless 路径。

同一窗口可以并行运行不同原生会话。切项目、选择另一会话、新建或打开工具页面都不终止既有回合；前端为各会话保留可返回的运行状态和审批入口。一个原生会话仍一次只接收一轮，创建后不能改换 CLI。

WebSocket 通过恢复握手将页签与后端稳定连接身份关联，短暂断开不立刻中断回合或拒绝审批。重新连接按序号补收，刷新可从缓存重建当前及后台回合；恢复前取消冲突的历史请求。缓存缺失时提示重读原生记录，不重复执行原输入；完整退出应用清理宿主管理的子进程，可选扩展的独立委派任务见[委派生命周期](agy-codex-delegation.md#生命周期与关联)；预算见[架构](architecture.md#44-历史与前端状态)。

AGY 账号和 Gemini API 的模型列表、偏好各自保存。历史按本机原生会话 ID 与目录读取。续发使用当前连接和其支持的模型，须通过原生续接与参数核对；真实跨认证续发尚未验收。

Codex 历史按已核实的本机 ID 与目录读取。续发时，原生可能因记录所属服务商与当前配置不符而拒绝；工作台显示该原因，并保留现有服务商、认证和历史。

打开 Codex 或 AGY 主会话先读取最近内容，对话与轨迹共用已加载范围；聊天页空闲时有限补读最近提问，后续可向上滚动、点击列表顶端或右侧导航入口加载更早记录。首屏失败时提示重读，不在未知上下文上继续发送；更早页失败时保留已显示的记录，可以在原位置重试，不改变已核实的续发状态。旧版原生明确不支持分页时，首屏才回退到有界全读。CLI 返回的会话身份须与当前项目和预期原生 id 一致。

### 工作区文件预览

`GET /api/projects/:id/file?path=...&view=content|diff` 只在点击时读取当前工作区的文件。文本通过已有安全文件模块有界读取，最大 256 KiB，拒绝越界、符号链接、Git 内部文件和非 UTF-8 内容。Git 改动以 HEAD 文件为基线，在独立临时目录比较读取到的正文，不执行项目过滤器或外部 diff；无 Git 基线与读取失败返回具体错误，不伪装成新增文件。浏览器查询按工作区、会话、路径与视图隔离，离开即取消并释放正文缓存。

### 图片、文件与媒体回放

附件在独立二进制 HTTP 接口上传，发送消息只带资产 ID 和 revision。上传及上传资产的预览同时校验本机认证、WebSocket 恢复身份、工作区和会话；恢复令牌只在 header，不出现在图片 URL。发送前再次核对真实版本、原生能力和当前模型，不能沿用旧缓存开启图片。AGY 账号选图只读取通道声明，不认证、不创建会话；Gemini API Key 的检查可在空会话内核对参数。两者都不发送对话输入。headless 仍仅开放文件引用。

| CLI | 图片输入 | 文档与通用文件 | 原生图片回放 |
|---|---|---|---|
| Claude Code | SDK base64 内容块 | 文本/PDF为原生 document，其余为明确文件引用 | 用户图片、工具结果图片、已核实归属的子代理图片 |
| Codex | image/data URL；避免新图片只保存旧本机路径 | 显式文字文件引用；mention对普通文件未生效，不采用 | 用户图片、旧localImage、本机imageView、MCP/dynamic工具图片 |
| Antigravity | ACP image 内容块；支持符合条件的 API Key 和个人账号，headless 不接收图片 | ACP 文本通过 resource 转为文件引用；其余同样使用引用 | 原生 userInput.media；工具图片未接入 |

单个5 MiB、单条8个/4张图/20 MiB，图片最大边16384、总像素32 Mi，动画最多100帧并计入总像素预算。PNG/JPEG/GIF/WebP按真实结构校验；实际解码仍由浏览器和原生执行，不自动转码或摘要。Codex媒体消息有32 MiB预算，其他消息保持8 MiB，收到后按具体类型复核，不截断大消息冒充完整结果。

上传缓存上限256 MiB，待发送资产24小时过期。只有经原生完成确认并已证明自持久的内容才转为可回收预览，7日未访问回收；运行租约和文件引用固定保留。Claude图片/文本/PDF、Codex与AGY ACP内联图片已通过隔离原生记录及续聊核验；普通文件与ACP文本引用不据此回收。缓存满时拒绝上传并说明，不删除仍被原生引用的文件。

历史媒体按已验证的原生会话、消息、块索引定位，网页不能传任意路径或远程URL。旧本机引用有界读取并拒绝目录/文件链接、身份或内容变化。Claude SDK按目录查不到Windows短路径记录时，仅在全局记录cwd等价后补救读取；不扩大到其他工作区。合成模型实测证明传输、保存和读回，不替代第三方模型实际视觉识别验收。

### 原生提问与表单

共享交互分为问题、表单和授权链接，拥有者分别是回合、原生会话或管理操作。CLI 回调映射到宿主随机交互 ID，答复只允许来自创建它的稳定连接身份；跨页面、重复、迟到和不符合原生约束的答案不能执行。回合外请求在独立收件卡片中显示 CLI、项目和服务来源，不随旧回合缓存回收；短暂断线、刷新后仍能答复。

Claude 的 `AskUserQuestion` 支持单选、多选和自由输入，提交交回 `updatedInput.answers`，取消映射为原生拒绝。`onElicitation` 支持表单与链接。专用 `onUserDialog` 只声明真正已实现的种类；目前列表为空，不代答未知 dialogKind。SDK 明确规定未知种类应留给原生超时处理，不能把取消响应冒充用户关闭。

Codex 的 `item/tool/requestUserInput` 按原生问题 ID 回答并核对线程、轮次和 itemId；原生撤销后关闭卡片。0.166.0 的阻塞问题在计划模式触发，取消使用经隔离验证的空 answers。默认模式的异步提问是 `agentMessage(delivery=async, questions)` 消息，网页按原生 session/message ID 去重，实时和历史共用非阻塞卡片；回答经服务端核题后作为追加输入。回合结束后仍可回答，后台归属、队列快照和已答历史保持一致；关闭页面保留未答状态。计划模式入口与异步答复均已接入。

AGY ACP 仅在安装了工作台交互处理器时声明 elicitation 能力；会话创建前的请求必须关联本实例在途操作，已有会话请求核对原生身份。表单提交/拒绝/取消分别返回 accept/decline/cancel，关闭实例取消等待；headless 没有此交互通道。

标准表单支持字符串、数值、布尔、单选与不重复多选，保留原生必填、范围和格式约束；未知组合、正则或嵌套对象明确拒绝。单次最多四题、每题二十选项，表单最多二十字段，答复最多 16 KiB。秘密字段以密码框填写，只直接交回原生，不写入宿主历史、缓存或 WebSocket 恢复数据。

授权链接只接受 http/https，由用户主动打开。Claude 的 elicitation_complete 与 ACP 的 elicitation/complete 按运行实例、服务和原生授权 ID 确认完成。Codex 独立 OAuth 流程见[原生配置](native-configuration.md#mcp-配置与运行管理)。

### 待发列表与本轮引导

运行中输入默认进入宿主队列，只有最新 `FollowupSnapshot.canSteer`、未暂停及本轮模型/强度/权限一致时提供显式引导。网页不以静态能力开启引导，也不在未知投递后切路径重试。queued/failed 的普通排队项按 revision 取回；收到带取回标记的已移除快照后才恢复到输入框。不兼容或已开始投递的条目不能转为引导。待发转引导需核对原项版本与本轮 ID，先移出下一轮调度，再使用原消息 ID 调用原生通道。unknown 只能核对历史后处理，移除仅删除列表记录。继续为用户显式动作，重连不自动恢复调度。

`followup.state` 与恢复握手的 `connection.followups` 共用快照处理。追加回执按 clientMessageId 绑定本页草稿，迟到回执不清不同的新输入；自动 `turn.started.input` 使用独立 clientTurnId 重建前台或后台轮次，不能将其与 followupClientMessageId 等同。引导确认单独按消息 ID 去重，保持原会话归属。

本页保留队列文字、技能和 File；256 MiB 页面预算包含所有会话草稿、队列和恢复备份，同一 File 引用只计一次。可信首次 session 绑定只提升已排队文件的 scope，普通草稿仍遵守附件身份变更重传规则。受理后释放队列 File，已开始轮次的附件备份保留至结果；后端身份失效则清旧资产引用并保留原文件，不自动重发。恢复草稿保存当前输入，已有附件备份独立保留；刷新后缺少原文件或技能详情时要求重新选择。

## 4. 接口与实现选择

既有 `ChatView`、`Composer`、工具卡片、审批卡片及 `TurnManager` 继续复用。`SessionPane` 将当前项目接入对话视图；新建按钮列出三个 CLI，未选会话时提供新建输入。

能力接口保持 `/api/workspaces/:id/agent-capabilities`：GET 仅读缓存，并通过 discovered 区分尚未获取和已获取的空结果；POST 用于首次打开模型菜单或手动刷新。既有会话传可选 `sessionId`，服务核实其原生目录后读取该目录能力，前端缓存区分会话；普通文本无需能力目录。

原生运行时已经返回并绑定的会话身份可直接确定能力读取目录，不等待历史摘要索引；这份进程内目录事实不用于授权历史读取或管理操作。未经过本进程确认的历史身份仍经原生归属接口核对。

模型持久缓存按实际 cwd 与 CLI 区分，项目记录 id 变化不导致重复发现；命令就绪使用独立 commandsDiscovered 标记。 Codex 已核实的 ChatGPT 模型目录只保留在内存，不覆盖已有的 API Key 或自定义服务目录。配置保存立即作废同 CLI 的内存、磁盘和在途发现。AGY 还按原生连接方式区分模型目录，打开模型或强度菜单时复核本机已保存的连接，不因此强制联网重刷目录；模式不明时不应用任一模式的显示偏好。失败只保留同一连接的已有可用模型，切换后迟到结果不得落盘。

新的原生交互契约使用 `features` 区分图片、文档上下文、提问、表单、引导及子代理的原生支持状态与工作台可用状态：`support` 可以是已支持、不支持或未知，只有 `available` 才表示当前接入可用。能力按 Claude SDK、Codex app-server、AGY headless、AGY ACP 的实际运行路径核实；发现目录不代表已有可用的会话运行实例。旧目录缺少此字段时保守关闭新交互，磁盘只保存模型元数据，不持久化运行功能标记，普通文本及既有子代理历史不依赖这些新增标记。

已核对的基线为 Claude CLI 2.1.317 / SDK 0.3.286、Codex 0.166.0、AGY 1.5.3。新交互还需成功握手和已完成的工作台接入；更高版本须逐项补充验证证据，不能仅凭版本号自动启用，也不预设支持上限。Claude 引导的调度边界及 ACP 的提问、表单、引导和子代理仍须单独核实。AGY headless 处理文字和文件引用，子代理历史走独立读取；ACP 的图片与嵌入上下文由当前握手决定。

模型的 `inputModalities` 采用原生报告；`featuresForModel` 据此控制图片输入与原生文档直读。文本上下文、文件引用和文档内容块在界面中分别标明。

会话级 `RuntimeControl` 独立于 `TurnHandle`，包含运行实例和原生会话身份、任务快照、逐任务停止及资源失效。Claude 与 Codex 已接入当前实例可核实的后台任务状态、租约和停止；AGY 仅支持整轮取消，不能据此推断可单独停止子任务。停止控制必须绑定原运行实例，资源失效不得中断活动任务。

日常浏览按来源分页读取摘要，再依据可靠工作目录归属项目；Claude SDK 的全局发现可能遗漏目录索引中的会话，因此 AgentDeck 按已登记项目目录逐个读取后合并分页；同一读取批次复用固定聚合快照，快照回收后旧游标失效，其他 CLI 使用全局原生目录再按路径归属。工作区标题数量是当前已加载结果的投影（另可能含尚未落盘的本页会话），不是原生 CLI 总数。服务端分页按钮加载后续页，不会因展开单个项目而枚举更多数据。“其他目录”使用 `GET /api/sessions/page` 的 `scope=unassigned` 查询，零项目也能使用。Claude 当前不请求 worktree 会话；Codex 使用 app-server 默认交互来源集合并排除归档，避免多值 sourceKinds 在当前原生版本中缩窄桌面列表。各原生界面还可能显示这些范围外的记录。旧 `GET /api/sessions?agent=...` 保留为全量无归属摘要的兼容入口。AGY 摘要库缺失或正常空表返回空；损坏、锁定等读取失败单独显示，不影响其他 CLI 或丢弃已载入的页。共享在途读取不缓存正文，取消一个查询不终止其他订阅者。

读取、续接、管理及分叉都复核原生目录。会话位于项目子目录时使用原生 cwd 执行，项目根只用于归属；多目录摘要无法唯一归属时拒绝操作。启动环境解析后重新核对实例容量，原生配置写入与项目换目录通过活动租约互斥。

`/ws` 沿用 `chat.send`、`chat.interrupt` 和 `permission.respond`。非法发送请求若带有效 `clientTurnId`，错误须回传该关联字段，避免界面永久处于等待状态。

Antigravity 使用本机 `agy --input-format stream-json --output-format stream-json`，输入为 `{"event":"user","message":{"content":"…"}}`。依据是本机帮助和[官方 headless 协议](https://antigravity.google/docs/cli/headless/)。每轮关闭 stdin，下一轮用 `--conversation` 续接；不依赖猜测的常驻控制接口。输出按 `event` 与嵌套载荷解码，处理 `init`、`step_update`、`result` 和 stderr。续接用摘要验证目录，成功结果仍等待真实进程退出；超时请求停止并保持占用，不能伪造退出成功。

Windows 桌面桥只允许同源主窗口启动固定的 `agy acp --login`。授权码粘贴到原生交互终端；窗口关闭前合并重复请求，正常退出后使能力缓存失效。账号状态读取见[原生配置](native-configuration.md#启动环境)。

AGY 1.5.1 的新摘要通常在进程 close 后才完整落库。本页通过已发送会话补充工作区导航，原生摘要到来后合并；不提前生成原生记录。已用 AGY 1.5.11 的原生历史核对，摘要表 `preview` 来自首条用户消息，而非最后一轮。`title` 为空时用 `preview` 的前 60 个字符作为显示标题，不修改原生数据、不以预览代替正文，也不为列表读取轨迹。公开 `agent_response.text_delta` 按增量显示，隐藏思考与签名不公开；原生可能从工具公开参数中删除 `toolSummary`，此时仅显示已知动作与参数。

Windows 冷启动时曾观察到原生更新器打开终端。工作台启动 AGY 对话、管理及发现进程时设置 `AGY_CLI_DISABLE_AUTO_UPDATE=true`，隔离对照显示更新器终端不再出现；AGY 1.5.1 要求 `true` 而非 `1`。独立 CLI 的更新仍由原生程序管理。

### Headless 回合结果

headless 普通消息在原生报告成功、流中和结果中却都没有文字时，显示「AGY 没有返回文字回复。」并暂停待发，不会重新投递输入。已有的明确错误或权限软拒仍按原有规则处理。重读历史时，只有完整回合结束于明确的空回复、且没有其他正文、明确错误或取消，才在该轮显示这条提示；跨页先拼齐，不凭单页空白断定。原生工具记录保留，不能由无正文判断工具是否执行过。

普通 stderr 不再直接当作错误。明确认证失败、HTTP 500、503 / UNAVAILABLE、权限软拒用固定脱敏说明，result、工具错误与 stderr 的同类提示去重；未知失败在排空双流并确认进程退出后兜底。500 只说明服务内部错误，不推断凭据错误或配置未保存。原生 auto 不支持且已回退时显示权限模式活动，不替用户改模式或重新请求。工具软拒也读取 `denied_actions`，原生 SUCCESS 仍保持原生结果语义。持续重试而未报告原因时只能显示等待，不能凭空判定 503。

HTTP 429、500、503 与 524 归为可重试服务诊断。headless 先暂存，待双流排空与进程退出后判定结果，续接错误按下文核对当前轮与历史记录。ACP 的当前 prompt 请求失败时保留已流出的正文、报告本轮错误并暂停待发；可重试只说明后续可以重试，不证明本轮完成，也不自动重发。API Key 与账号图片路径遵循同一失败判定。

原生明确报告 `Individual quota reached` 时，实时错误与历史错误均显示额度已用尽，并提示等待恢复或更换有额度的模型。此类错误不归入纯 429 自动恢复例外；历史中的相对倒计时不当作当前剩余时间展示。错误归属仍按原生输入边界核对，不因文案归类而转移到后续轮次。

AGY [官方 headless 协议](https://antigravity.google/docs/cli/headless/)在 2026-11-20 核对时明确：流式会话每轮发出一个 `result`，`response` 属于发出它的当前轮，`num_turns`、`usage` 和 `duration_seconds` 才按会话累计。因此每轮结果默认属于本轮，不能将整个 `result` 或续接的 `ERROR` 视为累计历史。较早真实 CLI 对接本机模拟服务曾完成失败、成功、再次失败三轮对照；另一次原生会话副本对照在本机成功响应后仍得到历史同文 524。后一次没有完整保留 stderr 分类与本轮轨迹，不能证明错误的唯一来源，也不能排除本轮再次失败。此前根据完整答复与退出 0 改成功，或将所有续接错误统一降为未确认，均超出了证据范围；历史过程见[复盘](incidents/antigravity-repeated-regressions.md#错误提示跟随续接回合)。

2026-11-20 的 CLI 1.5.12 隔离对照使用新 profile、独立目录、占位密钥和本机 HTTP 模拟响应，依次得到成功、524 失败、再续接完整答复三轮结果。第三轮仍返回与第二轮完全相同的 524 `ERROR`，自然退出 0 且 stderr 为空。共处理 3 次本机模型请求，另有 7 次外部代理请求被拒绝；未修改用户配置或向远端模型服务发送请求。该对照重现了当前版本的协议归属冲突，但不将同文比较提升为对任意当前失败的排除证明，也不代替远端模型验收。

续接的 `ERROR` 只有同时满足以下条件才归为 `outcome=unconfirmed`：进程自然退出 0；可信的本轮完整轨迹以公开答复结束；没有明确的本轮失败；非空错误文本与本轮输入前的原生错误步骤或明确回合故障严格同文。匹配源是结构化错误，不使用工具输出、普通 `TOOL_ERROR`、HTTP 状态码或诊断类别代替。此时保留 `isError=true` 以暂停待发，界面按[轮次提示规则](../product/ui-layout.md#71-用户可见提示)展示。当前 stderr、权限拒绝、直播终态步骤或原生轨迹明确证实的本轮错误优先，保留具体脱敏诊断；普通工具失败留在对应工具卡片。

同一回合只展示一个主要错误。AGY 的 headless、ACP 和原生历史共用已知原因的分类；本轮确认的原因优先，纯 429 不覆盖明确的最终失败。原生历史按轮次归并：末页可直接显示明确原因，向上补页不再追加同一错误；只有已加载完整的原生步骤显示纯限流后完成答复且无其他失败时，才不显示旧限流。工具自己的错误留在工具卡片。Codex 的原生 `failed` 轮次在实时和历史使用同一提示，中断不是回合错误提示。工作台不把进程退出、传输异常等临时提示写成第二份历史；Claude Code 的原生助手正文与工具结果仍按原生记录回放。

只读复核最多等待 5 秒，并核对会话、目录、空闲状态、可信的本轮输入边界和已收到的最大步骤索引。没有读取入口、读取失败、错误正文缺失或格式异常、边界不明、另一输入、尚未完成步骤、拒绝、超时或没有相同旧错误时，保留原生 `ERROR`，不泛化为未确认；核验可中断且不发送模型消息。只有符合未确认条件或已证实纯 429 恢复时，才在缺少直播正文时补齐同轮最终公开回复，并保留有依据的步骤统计；已有直播正文时不拼接轨迹全文或猜测后缀。证据不齐时不拿错误结果中的 `response` 补正文，也不把累计用量与耗时当作本轮统计。仅有完整答复或历史同文，均不足以独立改判。

本轮判定使用专用完整轨迹读取 `readTurnTrajectory`：首包必须提供有效 `numTotalSteps`；需要分页时，补页后重新核对会话身份、目录、空闲状态，以及步骤总数和首包步骤内容一致。总数缺失、分页不完整或核对失败时保留原生 `ERROR`，不以不完整快照推断成功或历史归属。各页分开读取，首包和总数用于发现变化。

纯 429 恢复保留为窄例外：同轮轨迹中已结束的已知纯 429 后有完整最终答复，身份、目录、输入边界与全部终态证据一致，没有其他失败且进程自然退出 0，才可确认恢复。错误正文为空不是独立成功例外；缺少同轮纯 429 证据时，完整答复也不能推翻 `ERROR`。未知格式或混合故障不套用限流规则。结果未确认的待发列表仍需用户核对后显式继续；这一状态仅存在于当前页面和有限恢复缓存，没有原生持久化契约，重新读取历史只呈现原生实际保存的记录。

结果到达后的进程清理单独判断：只有宿主确实发出了清理信号，退出为 0 或对应信号时，才认定为自身清理；这不构成模型成功或历史归属的证据，清理后的 `ERROR` 仍按失败处理。外部非零退出、未知或不相符的信号仍失败，用户主动停止不会判为成功或自动继续待发，也不会把尚未核实归属的结果报成停止的原因。工具失败留在工具结果；认证、权限等明确诊断在本轮结束时选一条显示。临时服务故障后已完整答复则不报；持续无进展而终止时显示已有的具体原因，不另报一次通用失败。

### Antigravity 的能力发现与历史

Antigravity 菜单模型目录在临时 home/cwd 中执行原生 models，只复制模型白名单，不加载用户 MCP、Hooks 或插件；临时更新检查标记避免原生后台更新器闪出终端。Gemini Key 与 ADC 认证分别沿用原生入口；账号模式交给 CLI 读取系统凭据，获取失败保留配置模型，不据此断言账号未登录。早期 1.5.1 已隔离验证两列 TSV；当时的已登录正向流程与文件回退认证尚未验证。当前各版本的验证结果见[路线图](../roadmap.md)。临时窗口启动的默认强度另从隔离的本机 GetAvailableModels 读取，目录按本轮实际启动命令缓存，应用内 AGY 安装变更后失效；读取禁止访问真实服务。真实对话的规则与插件继续由 CLI 加载。

Antigravity 命令及内建技能使用禁止外部请求的临时 Gemini 配置读取 `/help` 与 `/skills`，不走账号模式的交互登录分支；工作区与全局技能由只读 `GetAllSkills` 获取名称、路径与禁用标记。1.5.1 已核对工作区、CLI 私有、Shared 和普通全局的同名优先顺序。原生界面命令只列出实际接入状态，不伪装成模型提示词；模型、强度、权限与配置已有工作台入口。可调用技能在发送前重新核对身份和路径，再传斜杠名称，由原生 CLI 展开正文。版本变化导致目录格式或接口失配时停止对应能力读取。

Antigravity 主界面用原生 `StreamAgentStateUpdates` 的指定窗口读历史首帧；全量回放、旧版回退和子代理仍用 `GetCascadeTrajectory` 与原已有界补齐接口。读取核对会话 ID、唯一目录和父子身份；主会话首屏和管理操作要求空闲。用户输入与公开助手文本、已知工具、压缩和原生活动按白名单映射，内部签名、隐藏载荷及诊断正文不直接暴露；读取预算见[架构](architecture.md#44-历史与前端状态)。这些属于内部协议；本机读回与合成记录均不能推定其他 CLI 版本兼容。

管理进程先核对 ACP 身份，再用 `session/list` 引导本地后端；就绪依据是本次临时日志中与子进程 PID 匹配的 HTTP 端口，不等待账号会话列表返回。账号未就绪不阻断已经可读的本地历史；协议异常、进程退出、端口归属不符与取消仍终止该入口。

Claude 上下文沿用 summary 查询，回合用量取原生结果；计时在结果到达时截止，排除之后的上下文查询。Codex 总量仅在基线连续时计算回合增量，恢复但缺基线时不补造首轮用量。Antigravity 先保留已知步骤统计，不将不确定的 result 累计值当单轮结果。历史只展示能够读到的原生数据，旧会话缺少计时时不能还原精确生成速度。

三种 CLI 的会话路由均追加 `/subagents`：无查询时列出一级原生 ID 和摘要，`parentAgentId` 进入已核实的下一层，`agentId` 与可选 `cursor` 读取该层子代理历史。根会话身份始终固定；网页不能用任意子 ID 绕过原生父子链、唯一项目和目录核验。发现最多 128 个节点、10 层与 30 秒，Codex 与 AGY 的子代理图遍历累计最多 32 MiB；两者主会话分页和旧全量回放的独立预算不扩大此限制；循环、异常分页和超限明确失败。摘要只使用可核实的名称、角色和状态，缺失值保持未知。

Claude 继续使用 SDK `listSubagents` 与 `getSubagentMessages`；先读取首条消息的 `parent_agent_id`，父代理必须在同一根目录的原生枚举中。一级 parent 为 null，背景 Agent 的 task_id 与 SDK 子 ID 已在隔离记录中核对。历史目标页长 100 条，同一 API 回复整体留到下一页；超过页长时有界扩读至最多 1,000 块。单次子历史或媒体读取从入口共用 30 秒期限，包含枚举、摘要、正文及媒体复核；不接受最后一次迟到的成功。SDK 文件 API 不支持取消时，宿主有界结束等待并消费迟到拒绝，不能假称已取消 SDK 内部 IO。SDK 历史不提供当前任务状态，不能由末条回复猜测后台任务已结束。

Codex 从父历史 `subAgentActivity.agentThreadId` 发现子线程，同时要求 `parentThreadId` 与 `source.subAgent.thread_spawn.parent_thread_id` 匹配已验证父节点，depth 逐层递增；普通 thread/list 不能作为子线程目录。先核验元数据，再用原生 thread/turns/list 的 full/升序分页读取，内部 review、compact 与未知 source 别名不作为可浏览子代理。父 app-server 退出后的独立读取已通过隔离验证。

AGY 普通子代理从 `invokeSubagent.subagents` 与 `results[].conversationId` 发现，核对唯一 workspaceUris、parentConversationId、rootConversationId、nestingDepth。1.5.14 的 Swarm 与工作流从对应工具步骤的结构化 `stepRenderInfo.contentBlocks[].agent` 发现，不扫描工具输出正文；Swarm 仍核验 parent/root/depth，工作流另核验 `sourceMetadata.tool` 中的父会话、步骤索引与工具调用 ID。读取通过独立只读轨迹接口承接活动快照，原有分页预算保留。Swarm 的 IDLE 不表示完成；父步骤明确报告 Killed 时显示已取消；工作流子代理须有已完成的 FINISH 步骤才标完成。管理操作仍只针对空闲主会话。

独立视图保留自身正文、工具和已保存的用量，移除父会话分叉位置；媒体定位保持根会话与子代理 ID，并在读取时重新核实父子链。正式 reader 明确判定不存在或归属不匹配的兄弟节点只从目录淘汰，不阻断已核实的其他节点；根和被选节点仍须通过校验，超时、取消和运行失败继续使读取失败。正文、用量与详情选择不并入父会话。关闭视图释放查询缓存，打开或刷新重新读取原生快照。历史视图只读，活动任务的查看和停止使用[原生后台任务](#原生后台任务)入口。

Claude 历史恢复 `assistant.message.usage` 为模型步骤用量，按 API message.id 合并同一次回复的多块记录，统计只放在最后可显示块之后；不把 transcript 完成时间当成生成耗时。SDK 0.3.286 的历史入口不返回完整上下文报告；当前 Codex thread/read 契约没有 tokenUsage；Antigravity 历史已提供上下文估计，但只有单次完整生成的索引、执行身份和用量均一致时才显示生成计时与均速。这些是读取契约边界，界面显示未知值，不用模型名称猜窗口或用时间戳差值补统计。

原先禁止运行中切换的临时限制已移除；导航只改变当前展示，运行事件继续归属原会话。断线保留受恢复预算约束，长期离线仍会中断。

回复型号独立于会话配置。Claude 使用消息自身的 `model`；AGY 使用生成记录的 `chatModel.responseModel`，仅当来源轨迹、cascade、绝对步骤、执行 ID 与生成条目的单一步骤一致时采用。protobuf 省略的生成零索引按 0 处理，历史分页保留轨迹 ID 和生成偏移；缺身份、内部枚举与非法型号不补猜。生成耗时仍另行核对单次尝试及用量，不因取得型号而放宽统计条件。

AGY headless 的文本事件携带原生步骤 ID。结束后的历史补读最多等待 5 秒，只给当前视图同一轮、相同原生步骤的回复补型号；已有实时上下文继续保留，正文、终态和菜单选择不改写。新轮次、切换身份、超时或冲突报告会放弃补齐，失败不影响发送。ACP 当前只有会话身份与文本块，尚无可靠的回复步骤桥接，型号在原生历史重读时恢复。Codex 0.170.0 的消息与轮次 schema 未提供实际型号，轮内首次 `model/rerouted` 也不含回复 ID，故不用于逐条标注。

### 4.1 会话引用读取

稳定引用格式为 `agentdeck://session?workspace=<项目ID>&agent=<CLI>&id=<原生ID>`。共享解析器严格校验协议、字段和身份，兼容已有 HTTP(S) 网页片段；解析不会访问链接指向的网站。引用只定位本机工作台中已登记的工作区，不承担跨机器共享正文或改变会话归属。

发送普通消息或原生引导前，`sessions/references.ts` 按引用自身的项目、CLI 和原生 ID 核对归属并定位文件，将路径与读取说明附入本次原生输入。只定位元数据，不预先把引用正文装入提示；引用 B 不改变当前 A 的身份。定位失败在对应引用说明中保留原因，原始用户输入继续保留。

Claude Code 定位原生项目目录中的 JSONL，Codex 使用原生 `thread/read` 报告的磁盘路径；不推测 rollout 文件名。接收方使用自己的文件或终端工具读取，按问题检索或按行分段，明确要求完整阅读时读取全文。

AGY 1.5.14 的记录在 `~/.gemini/antigravity-cli/conversations/<原生ID>.db`，正文为 Protobuf 字段。发送时同时提供 `sessions/read-agy-history.ts` 的命令描述；它调用既有原生历史范围接口，默认输出最近一页，`--before` 读取更早页，`--all` 在同一只读进程中遍历。输出按页从新到旧，每页保留原生时序、步骤身份和用户、助手、工具、活动、可见错误与轮次终态。此入口不注册扩展、不保留正文文件，也不让每次小段读取重新加载全量历史。桌面随包分发 `read-agy-history.mjs`，由主进程传入准确位置，命令只为读取进程设置 Electron Node 模式。

## 5. 验证

常规自动验收使用受控运行器和合成原生事件验证发送、续接、审批、停止、错误、权限软拒及进程清理；本机 `--help` / `--version` 可运行。真实模型请求仅在用户明确授权后按既定预算单独进行，使用隔离目录，不修改用户原生配置或 SSH 数据。

前端验证须覆盖三个 CLI 可选、历史失败禁发、原生步骤回放、目录缓存复用、默认参数继承、输入法与停止，以及运行中导航后的事件和审批归属。执行轨迹另核对跨轮 ID 复用、右栏详情、审批、缺失统计与速度口径；使用隔离的本机服务检查页面，不把受控测试写成真实模型验收。

类型、代码质量、构建及相关回归通过后记录命令与证据；原生 CLI 升级后协议仍可能变化，失败只影响对应适配器。

最新源码验收、实际 URL/Key 结果和账号模式暂缓状态集中在[路线图](../roadmap.md#已有验收证据)。2026-11-09 的有限真实闭环与旧 AGY 参数错型实验保存在 `b053fe1:docs/engineering/native-dialogue.md`，不得描述成当前服务均可完成任务。

原生主模型、标题和安全检查可能使用不同模型渠道，主模型成功不代表辅助请求可用。工具参数错型由原生 schema 拒绝；工作台不修写响应、不替换辅助模型或放宽原生安全判定。

## 6. 会话管理接入

会话菜单在应用内提供已接入的管理操作，使用同一项目归属校验、空闲锁、确认与分支对话框。Claude 使用 SDK，Codex 使用 app-server；Antigravity 借助本机 agy 启动的原生会话服务完成操作，不要求打开终端，也不手动复制轨迹或删摘要行。

主界面通过 `GET /api/sessions/page` 分页，scope 区分活动、归档与无归属；search 检索未加载的原生摘要，cursor 继续读取。旧 HTTP 列表端点仅保留兼容，网页不再调用。分页预算见架构。读取和写入统一以 `/api/projects/:id/sessions/:agent/:sessionId` 定位，写入分别追加 `/actions`、`/fork`。动作、全量历史和分叉不接受查询字段；Codex 和 AGY 主界面追加 `/history-page` 读取最近记录，历史游标通过可选 `before` 传入。响应统一禁止缓存。

工作台 `/resume` 是本地导航，不把原生交互式命令传给模型。它按当前项目 ID、CLI、活动范围和搜索词查询 `/api/sessions/page`；选择时重新确认当前选择和目标身份，再沿用打开原生会话的路径。下一次用户发送时才按原生会话 ID 续接。AGY 的 `/switch`、`/conversation` 与其[原生交互命令](https://antigravity.google/docs/cli/commands/resume/)语义相同；终端参数 `--continue` 续接最近的一条，`--conversation <id>` 指定一条，与工作台不自动选中的搜索框不是同一个入口。已选原生技能的参数不作为工作台命令解释。

归档页同时查询三个来源。Codex 仍按原生归档/恢复执行；Claude、Antigravity 使用工作台身份标记，不改 CLI 历史。归档会话必须恢复后续聊或创建分支。删除需确认实际范围；会话忙时拒绝管理。分支成功只在原选择代次仍有效时打开新记录，其他情况刷新来源列表。

Antigravity 的公开 ACP 初始化目前没有 fork/delete 能力，已验版本 1.5.1 的原生服务则包含 `ForkConversation`、`DeleteCascadeTrajectory`、`UpdateConversationAnnotations`。适配器通过自己启动的 `agy acp` 引导本地服务，只接受该进程日志中匹配 PID 的 HTTP 回环端口。管理请求限固定方法，不发模型 prompt，不连接其他进程或用户提供的地址；内部协议升级失配时返回操作失败，不尝试修改 SQLite 兜底。

写入前用原生轨迹核实会话 ID、唯一工作目录、空闲状态和非内部子代理身份。创建分支按已完成原生步骤执行，再核对新 ID、目录、父引用和摘要落库；删除轨迹后以 `JetboxDeleteSummary` 清原生索引，确认两者均已移除。若轨迹已删而摘要清理中断，重试必须重新验证摘要身份与目录，且只有明确的原生 not_found 响应才进入补清理；接口不存在或通信错误不能当作会话缺失。

管理器关闭自己的进程、请求和临时日志，应用退出时统一取消待启动操作。隔离验证用原生空会话与合成已完成步骤，不能代替真实账号模型回合验收。

## 原生权限模式

输入区手动选择的权限用于当前会话后续轮次，并成为工作台内同一 CLI 的新会话默认；工作台不改写 CLI 配置文件。已建立的其他原生会话仍按自身权限续接。首次打开工作台读取各 CLI 的默认值，切换项目、CLI 或新建会话使用已读缓存；没有选择时由原生决定。首轮发送时冻结选用值，随后改默认值不影响已发送或已排队的内容。所属会话运行/准备/管理及权限读写期间禁用修改，读写未确认时暂缓受影响的会话发送。

`GET /api/sessions/permission-defaults` 读取工作台默认，`PUT /api/sessions/permission-defaults/:agent` 在未建立原生会话时只修改对应 CLI。已有会话仍用 `GET/PUT /api/projects/:id/sessions/:agent/:sessionId/permission` 核验项目与原生身份；手动写入在会话空闲锁与项目租约内同时保存该会话权限与对应默认。发送时沿用现有权限字段；续接未传时由 TurnManager 读取该原生会话的设置。首轮只在核实原生 ID 后保存会话自身快照，回合结算不会推回新会话默认；写失败单独提示，不重试模型任务。存储格式见[会话权限偏好](native-configuration.md#会话权限偏好)。

| CLI | 菜单选择 | 原生映射 |
|---|---|---|
| Claude | 手动审批、接受编辑、自动审查、计划模式、不询问、跳过权限检查 | SDK permissionMode: default、acceptEdits、auto、plan、dontAsk、bypassPermissions |
| Codex | 请求批准 | workspace-write + on-request + user |
| Codex | 帮我批准 | workspace-write + on-request + auto_review |
| Codex | 完全访问 | danger-full-access + never；不创建自动批准回调 |
| Antigravity | 接受编辑、自动模式、计划模式 | --mode accept-edits / auto / plan |
| Antigravity | 跳过权限检查 | 显式 --dangerously-skip-permissions |

Claude 仅显式 bypass 时设置 SDK 的 allowDangerouslySkipPermissions。auto 使用 Claude 原生分类器；Codex 自动审查也由原生执行，不在网页静默回答权限请求。Antigravity headless 仍没有交互批准通道，不把软拒伪装成已允许。

AGY 手动压缩先通过 headless 取得本轮 checkpoint，附带的继续消息再按原模型、权限及附件的正常路径启动同一会话。原本可用 ACP 的继续消息仍可交互审批；压缩失败或中断时不发送继续消息。工作台保持一个操作的结束状态，原生记录中保留压缩与继续输入。

Codex 的 MCP 工具确认也进入现有批准/拒绝流程：仅接收带 `codex_approval_kind: mcp_tool_call` 的原生空对象表单，按 `accept`、`decline` 或 `cancel` 返回本次决定。具有输入字段、组合约束或 URL 登录流程的请求不能当作简单工具确认；取消后迟到的批准无效，不增加持久授权。工具说明与参数由原生请求提供，不能因为菜单允许某种模式就自动批准。

AGY 实时工具以 `DONE` 或 `ERROR` 结束；失败及时回填工具结果，保留原生错误和耗时，不再等到回合结束后仅显示“未完成”。无结构 stderr 只判断诊断类别，不从句子中猜工具名。其通用 `call_mcp_tool` 在 1.5.1 对 Arguments 缺少对象类型约束，模型返回 JSON 字符串时会直接传给 MCP，标准服务会拒绝。原生按工具 `eager` 加载可避开这一包装，设置方式见[原生配置](native-configuration.md#antigravity-mcp-工具加载)；不由工作台私自更改用户 MCP 规则或修写模型返回参数。

Codex 已有会话会恢复历史权限，所以用户显式选择“重置权限”使用单独的 native 动作：先创建不持久化的空线程，让原生解析当前有效配置，读取审批策略、审查对象及权限 profile/沙箱后取消订阅，再显式用于正式会话续接。空线程不发送 turn/start 或模型 prompt。必要字段缺失就停止，不能省略字段后误回到历史的完全访问。无选择的普通续接仍尊重原生会话，不强改其权限。

菜单列出已核对协议支持的模式；组织策略、账号/模型可用性与 CLI 版本仍由原生校验，不能把菜单可见当成账号已获权限。原生拒绝时本轮停止并显示错误，不降级策略、不换模式重发。Codex 权限字段拒绝使用固定说明，不泄漏原始 RPC 错误中的路径、配置或凭据。高级自定义 permission profiles、Claude rules 和其他原生细项仍走原生配置，常用预设不覆盖未显式选择的值。

依据：[Claude 权限](https://code.claude.com/docs/en/permissions)、[Agent SDK 权限](https://platform.claude.com/docs/en/agent-sdk/permissions)、[Codex 权限模式](https://learn.chatgpt.com/docs/permission-modes)、[Codex 自动审查](https://learn.chatgpt.com/docs/sandboxing/auto-review)、[app-server](https://learn.chatgpt.com/docs/app-server)。本机 SDK 类型、Claude/agy --help 和 Codex 生成 schema 已核对；这不等于真实模型回合验证。

## 原生后台任务

Claude 和 Codex 的任务状态独立于父回合。后台任务仍活动时，工作区目录更换、会话管理、CLI维护和闲置进程回收保持阻止；停止等待原生确认。网页短暂离线只暂停待发队列，任务快照可恢复，恢复身份永久失效则关闭本页拥有的原生实例。

Codex 后台终端停止或清理成功后，须重新读取完整列表确认终端已消失；操作前仍在途的刷新结果不能用于这次确认。

Claude使用原生全量后台集合及stopTask，Codex先验证子线程的cwd、双parent与depth，再按当前子turn中断；两者只控制本宿主实例确知任务。后台子代理工具批准绑定原创建页面，通过session级请求回答，不能结束或污染父回合。Claude原生禁用子代理AskUserQuestion，Codex默认子代理未开放异步提问；不伪造问题支持。AGY只读子历史与整轮停止保持，尚无独立子任务停止证据。
