# 架构

本文记录原生 CLI 工作台、配置、插件和桌面的实现。会话协议见[接入说明](native-dialogue.md)，验收范围见[路线图](../roadmap.md)。早期实现说明见 `c686ef2:docs/engineering/architecture.md`。

## 1. 分层与职责

```text
Electron 主进程（apps/desktop）
  └─ 本机 Fastify（apps/server）
       ├─ HTTP + WebSocket → React 页面（apps/web）
       ├─ 项目、原生会话、CLI 适配、配置与能力目录
       ├─ 工作台插件注册、权限与静态页面服务
       └─ SSH Console：连接池、主机信任和凭据
共享协议与校验（packages/shared）
```

Electron 负责入口、生命周期及本机路径访问。目录选择与“打开路径”都只暴露窄 IPC，核对主窗口、主 frame 和同源页面；导航或销毁后丢弃返回值，插件 iframe 无权调用。打开路径只接受绝对路径，失败时把系统给出的原因回传页面，不静默成功。业务服务与浏览器调试共用一份实现，但浏览器调试没有这两项桌面能力。CLI 在本地项目目录执行，模型请求由 CLI 发起；服务器操作经 SSH 由用户触发。

会话和工具各自持有运行状态。自有插件宿主管理内置 SSH Console 与本地安装的静态页面插件；外部插件只通过声明权限的固定接口访问宿主，没有通用 Node 执行能力。包和消息契约见[工作台插件接口](workbench-plugins.md)，不包含 DSH 兼容层。

## 2. 技术栈

| 层 | 当前选型与职责 |
|---|---|
| 运行环境 | Node.js 22+、TypeScript 5.9，开发服务使用 tsx |
| 桌面 | Electron、electron-vite、electron-builder；隔离渲染进程与本地 Windows 打包 |
| 后端 | Fastify 5、WebSocket、zod 参数和配置校验 |
| Claude | Agent SDK 作为协议客户端；本机可执行程序作为驱动目标 |
| Codex | 本机 `codex app-server`，stdio JSON-RPC |
| Antigravity | 本机 `agy` 流式子进程与独立原生管理服务；Node 内置 SQLite 只读摘要 |
| SSH | `ssh2`，exec、SFTP 和远端 PTY 共用连接但独占通道 |
| 前端 | React 19、Vite 8、Tailwind 4、Ariakit、cmdk、react-resizable-panels |
| 状态与通信 | zustand、TanStack Query、partysocket |
| 消息与编辑 | streamdown、react-virtuoso、CodeMirror 6 |
| 终端与字体 | xterm.js/fit/search、系统界面字体与随包分发的 JetBrains Mono |

精确依赖版本由各 `package.json` 和锁文件维护，选用理由见[现行决策](decisions.md)。不因服务器使用 Python 而改写本地后端；涉及统计或分析时使用服务器已有环境，不自动安装依赖。

| `apps/server/src/http` | 访问控制与请求生命周期，对话和设置接口分别在 conversation 和 settings |
| `apps/web/src/app` | DSH 外壳、导航、布局和跨功能组合 |

| `apps/web/src/builtin-plugins/ssh-console` | 内置页面注册、服务器档案界面与控制台 |

| `scripts/dev` | 文档检查、受控夹具和显式真实链路验证入口 |
| `scripts/packaging` | 本地成包检查与隔离桌面启动冒烟 |

按功能划分模块，通用能力才进入公共目录；不额外增加控制器/仓储等重复层。旧同步、版本、本地镜像、Agent→SSH 桥和命令黑名单目录已删除；当前会话读取 MCP 属于独立只读能力。

依赖方向由少量 ESLint 导入规则检查：platform 不导入应用/CLI/插件业务，agents 不导入应用服务，插件宿主不导入内置实现；前端 cli/lib/ui 不反向导入功能页面，conversation 不反向导入实时 chat，shared 不依赖 apps。CLI 配置通过 `CliConfiguration` 静态注册，通用设置只负责 revision、文件保存、连接事务和失效通知。JSON/TOML 格式工具不识别具体 CLI，原生字段和作用域只在各适配目录声明。

会话目录的同步路径裁决与磁盘 realpath 核验保持不同函数。列表优先使用 provider 声明的能力；缺少声明时，`legacySessionCapabilities` 仍为服务端列表及旧响应提供兼容值。前端继续只有一个 chat store，纯状态和模型策略另行提取，不复制三个对话产品。


## 4. 项目、会话与回合

### 4.1 项目及归属

项目存储串行读写，保存时校验 schema 与唯一 id，将完整内容写入同目录临时文件后原子替换。新增或更换目录时校验路径存在；已有目录离线时仍可改名或移除。项目记录只有名称、本地目录和 id。

`agents/common/history/session-ownership.ts` 只比较规范化路径，不访问磁盘。Windows 盘符/UNC 使用 Windows 语义，POSIX 路径保留大小写；Antigravity URI 只接受 `file://`，支持 JSON 数组、单值及换行/分号列表。归属顺序和无归属行为定义在需求 F2。

日常列表使用 `GET /api/sessions/page`，按三 CLI 各读取一页，每页最多 50 条摘要；新增项目不增加来源请求数。Claude 使用 SDK limit/offset，Codex 使用 thread/list 游标，AGY 使用只读 SQL limit/offset；原生接口内部的文件扫描成本仍由 CLI 决定。共享层先核对项目归属及原生/工作台归档，再匹配标题、来源、会话 id、项目名称和目录。单次筛选最多扫描 8 个原生页；未找到足够匹配时返回继续游标，空页带游标不能解释为全部搜索结束。

原生页在同一浏览页面读取批次内复用：最多 32 页或 4 MiB，按最近使用淘汰已完成页，正文不入缓存。同页并发订阅独立取消，全部离开才取消底层请求。重开页面使用新的读取标识，避免复用外部 CLI 操作前的旧首页；运行首次绑定 id、回合收尾及管理操作按来源作废缓存。投影游标包含来源代次与查询/项目配置指纹，失效后前端回到首屏，不合并新旧分页。项目改名、换目录、移除后也更新搜索查询；非活跃页面查询保留 10 分钟，失效摘要不再用于项目忙态判断。

旧项目列表和全量来源接口保留兼容；其十万条检查只作结果超限保护，主页面、归档、其他目录和命令面板不再通过该路径全量读取。正文仍仅在选中会话后读取。

单条读取、续接和管理先核实原生目录，再验证其唯一项目归属。项目包含子目录时，运行器与能力刷新使用会话的真实目录，不能替换为项目根；Antigravity 多目录摘要没有唯一归属则拒绝续接。

会话摘要可携带经原生字段解析的单一本机 `directory`，用于添加项目预填；该字段不作为授权依据。目录变更与项目移除和活动回合、原生资源写入互斥，锁内修改防止检查后又开始新操作。前端换目录后清该项目的会话与能力缓存、取消旧历史，并按选择身份决定是否重置当前主区；新增、换目录、移除项目均刷新全部会话摘要，及时更新无归属及重叠项目的归属。

Claude SDK 的 lastModified 为文件 mtime，工作台对当前页读取 JSONL 尾部最多 256 KiB、同时最多 6 个文件，以最后一条主会话 user/assistant 的时间修正摘要；忽略元数据和子代理，无法取得可靠记录时保留 SDK 值。项目键与 SDK 一样先解析真实目录，规范化已有目录以减少路径别名影响；Windows 8.3 路径在 CLI 与 SDK 间仍有存储键差异，不能据此承诺完全兼容。只读原生文件，不修改时间或正文。SDK 游标仍按文件时间推进，已加载条目按修正活动时间排序，不承诺尚未加载全集的严格活动时间顺序。

### 4.2 CLI 接入

| CLI | 原生来源 | 已接入运行路径 |
|---|---|---|
| Claude | SDK 会话列表、历史、改名/删除/分叉 | 探测与回合共同定位本机程序；SDK 仅作为协议客户端，界面承接原生审批 |
| Codex | app-server 原生会话、工具与审批 | 省略未选择的参数，按需加载能力，回合和管理均绑定原生身份 |
| Antigravity | SQLite 摘要、时间和 `workspace_uris`；原生服务读取历史步骤 | 支持的Gemini会话使用ACP；自定义模型等选择保留headless，发送前选定路径；原生服务提供历史和管理 |

探测运行本地版本/帮助命令，Codex 另检查生成的协议 schema；每个 CLI 单次探测超时为 5 秒，输出有独立上限。stdout 与 stderr 一起核对，四态结果不意味着登录成功或真实模型请求已通过。

`runProcess` 用 `shell: false` 和隐藏窗口启动，支持 stdin、独立环境、AbortSignal、输出上限和超时。长期对话管道由各适配器管理，prompt 不写进命令行参数。

原生插件管理通过固定 CLI 参数数组和安装进程 runner 执行，prepare 不运行安装，宿主 operationId 负责幂等、进度与取消。命令确认绑定原生 SHA-256，配置秘密只经 stdin；操作全程持有既有维护/项目租约，能力失效与进程清理完成后才发布终态。Codex 插件不使用官方标为不可生产使用的 plugin RPC，配置层级读取使用 config/read，离线目录来自本地配置与安装缓存。接口与能力差异见[原生配置](native-configuration.md#原生插件管理)。

### 4.3 回合控制与原生参数

`TurnManager` 在准备前建立轮次，用 Agent+原生会话 id 占用会话；改名、删除、归档与分叉复用同一占用边界。停止取消准备或交给运行器中断，错误和结束都必须释放资源。

前端允许运行时切换项目、查看或新建其他会话，也可打开插件和归档页。chat store 保留当前视图投影，离开的会话进入内存后台表；稳定的本地 conversationId 覆盖尚未返回原生 id 的准备阶段，事件依据 clientTurnId/turnId 更新所属会话。正文、草稿、模型/强度/权限、审批及轨迹视图各自保存，切回时恢复；当前投影不在后台表重复保存。左侧可返回后台运行、待审批和未读结果，停止只针对目标回合。历史加载切走时取消，重新打开时重读；后台正在运行的内容不被历史请求覆盖。短暂断线及页面刷新按恢复协议补收，超过保留条件时才收尾；完整退出应用仍停止执行，具体预算见下节。

Claude/Codex 的运行时按会话复用，空闲回收预算为 5 分钟。缓存身份含项目、原生 id 与启动参数；关键输入变化后重新启动，崩溃实例淘汰，关闭应用统一 dispose。Antigravity 的 headless 和 ACP 均在本轮结束后清理进程，下一轮用原生 id 续接；已有会话的启动环境快照独立保留，在模型配置保存或显式重启后刷新。

模型/强度/权限未选则沿用原生默认；AGY 自定义窗口的临时标签路径会补齐经原生目录确认的默认强度，以保持原变体语义。权限选择携带 CLI 身份并经消息 schema 校验；各 CLI 独立映射原生模式。权限变化先回收当前会话的旧配置运行实例，再以相同原生会话 id 续接，切回原生配置也不复用原宽权限进程；Codex 显式恢复时另取原生生效默认并覆盖历史权限，不把省略参数误当作撤销。原生权限配置决定是否请求审批，宿主只承接答复。Antigravity ACP 映射原生批准，headless 路径显示权限软拒。能力 GET 返回缓存，输入区选中会话即预读；模型或强度菜单首次无缓存、旧 v1 元数据升级或用户重新获取时发 POST，失败不循环重试；既有会话带 `sessionId` 解析原生目录。模型缓存按规范化 cwd 与 CLI 保留独立目录映射，v3 对同一 CLI 的相同模型快照只存一份；Claude/Codex 兼容读取 v1/v2，下次成功保存升级。每 CLI 至多 32 个目录，单文件不超过 256 KiB。字节预算不足时先淘汰旧目录；单个完整目录本身超限则保留原缓存，不截断型号。只保存公开模型字段和默认值，不保存命令调用、技能路径或认证材料。

能力内存按每 CLI 最近 32 个目录或 2 MiB 回收，保留最新目录及在途读取/刷新。相同目录磁盘读取共享；模型查询在非活跃 10 分钟后可释放，再打开读取服务端/磁盘缓存。命令目录回收后保留最多 128 个轻量身份标记，显式执行已发现命令时补取并验证当前目录；从未发现或配置已失效的旧选择仍拒绝，不把未知命令发给模型。保存原生配置清内存、磁盘及补取标记，在途旧结果不得回填。commandsDiscovered 继续区分模型快照与当前进程命令目录。

启动环境异步解析完成后再次核对实例预算，防止并发准备越过 32 个实例上限。

能力发现前检查目录；既有会话在原生归属读取前先检查项目根，再按已核实的会话目录发现。失效目录返回专用错误码并连接更换目录操作。模型反馈与技能反馈分别输出，避免一个分支失败影响另一分支的界面状态。

AGY 模型快照除目录和 CLI 外，还按原生连接方式区分账号登录与 Gemini API。旧快照缺少连接身份，不返回候选和默认值；GET 只读原生设置和对应缓存，不启动发现或重写文件。刷新失败只保留同连接身份的候选；切换后迟到结果不能回填。用户下次打开模型入口时仍可发现，成功结果可跨进程复用。

Codex 能力发现只在原生 OpenAI 服务且无自定义地址或启动 Key 覆盖时读取账号状态。只有已核实的 ChatGPT 模式使用独立的显示范围，其模型目录不覆盖原有磁盘目录；API Key 和自定义服务保留原行为。额度为显式只读请求，服务端重新核对当前生效配置和账号。

### 4.4 历史与前端状态

zustand 持有当前项目、CLI、会话和回合状态，TanStack Query 管项目、历史、设置等服务数据。选择变化取消旧请求，并用会话身份/代次防止迟到结果串线；历史失败禁止在未知上下文上续聊。前端兼容旧适配器的 501 能力限制响应，当前 Antigravity 提供原生历史读取。

后台可重读正文保留最近 8 条空闲已读会话，并设 4 MiB 序列化字符估算预算。超过时仅释放正文和衍生显示状态，保留原生身份、标题、模型、强度和权限，返回时重读。运行、待审批、未读、草稿、历史错误及不可回放内容不会因预算被丢弃；AGY 需先有成功回放证据才能参与回收。这是可回收正文预算，不声称所有内存受同一硬上限限制。

左栏占满窗口高度，中央标题栏随对话或插件切换；右栏默认显示当前会话信息，选中执行步骤后改为详情，每次启动关闭。SSH Console 经左上导航首次打开后保持挂载，隐藏期间暂停观察。具体尺寸与窄窗互斥规则见[界面约定](../product/ui-layout.md)。

事件投影、时间线和轨迹由实时与历史共用，操作由宿主显式提供。实时使用 ChatView、Composer 和原生审批；历史时间线及其只读步骤详情不挂接实时应答或分叉，图片使用记录的项目、CLI、会话及子代理身份。时间线采用 react-virtuoso，读取工具白名单分组每段最多 40 项；审批、执行与错误独立成卡。只读与实时界面的验证不能互相替代。

执行轨迹从同一 ChatItem 数组投影，按用户消息划分轮次并逐步骤虚拟化。工具、活动和步骤统计使用界面独立 key 保存原生 ID，回填只匹配当前用户轮次；同轮重复结束更新原条目，不累计重复结果。`activity` 保留非工具步骤的名称和状态，缺失结果在收尾时标为未完成。右栏只引用选中条目 ID，后续结果更新直接反映在详情中。

`turn_end` 与 `step_usage` 分别携带对应范围的 token，`tool_result` 可附原生或本机观察耗时。前端只对范围匹配的输出量与有效耗时计算均速；明确整轮失败或取消时不使用本轮速度。结果未确认时，只采用经可靠轨迹复核的已完成最终回复步骤统计，耗时不足则不计算速度。没有本轮有效速度时允许展示同一会话已加载的旧值，标记“最近一次”，不跨会话复用。上下文使用独立 `context` 事件。统计数据仍只随本次原生读取和实时事件存在，不建立持久遥测副本。

Codex 主对话与执行轨迹使用同一历史分页入口。原生 `thread/read(includeTurns:false)` 校验身份和目录；`thread/turns/list` 倒序请求最多 3 轮，展示时按时间正序。8 MiB 普通 JSON-RPC 单条传输超限时重连只读客户端并降到 1 轮；仍超限则读取轮头，并用 `thread/items/list` 以 16、4、1 项逐级缩窗。确认含支持的媒体类型时单条上限为 32 MiB，这不是会话总量上限。单项仍超限或旧版不支持步骤分页时标记未读部分，仍可访问更早的轮次。新的媒体定位用原生轮次与条目 ID，不以全量历史查找。取消或失败不会覆盖已显示的页；分叉操作先核验原生轮头及空闲状态，并要求原生只返回新会话元数据。仅旧版明确不支持轮次分页时，首屏回退原有有界全读。

Antigravity 主对话与执行轨迹使用 `/api/projects/:id/sessions/:agent/:sessionId/history-page`，不把全量历史读入工作台后再裁切。现有后台管理进程先通过空步骤窗口取得范围与轮次，再读取原生更新流的首帧并关闭；首屏和向上翻页均优先取最多 3 轮、最多 96 个原生步骤。游标核对会话、轨迹与步骤范围；每次读取核对项目目录及返回的绝对索引，切走时取消在途请求。原生历史首帧预算为 8 MiB；超限先用原生紧凑格式，再缩短范围，单步仍超限则在原位置标明跳过。历史图片另按绝对原生索引读取单步，首帧预算为 32 MiB；明确不支持窗口时回退旧回放。长回合分段后只在补齐、能核实结尾时结算及显示分叉点；分叉前重新核对绝对步骤，不使用裁剪后的首包长度。可选的生成元数据单独限 4 MiB，只补充能核对归属的生成耗时；仅最新页提供历史上下文估计，旧页不会覆盖它。历史工具耗时不与模型用量混算速度，实时 headless 不生成缺失的上下文值。

对 AGY，原有全量历史接口保留，只有原生明确不支持分页时首屏才退回它；显式全量读取仍受原生首包与分页累计 64 MiB、50000 步、64 页及 30 秒分页预算限制，超限不误报配置错误。回合复核、常规管理 RPC 及子代理图仍使用原有 32 MiB 边界；全量或分页读取都只映射已知文本、工具、压缩和活动字段，不直接展开未知载荷。

partysocket 的连接退避为 1–15 秒，发送缓冲关闭。`ResumeHub` 用随机页签令牌与单调序号管理稳定 Socket，心跳每 15 秒检查半开连接；断开后保留 60 秒，完成回合保留 5 分钟。每身份最多 16 MiB、进程合计 64 MiB、最多 64 身份，大小按字符串内存估计并计入条目开销。超限停止对应回合；容量拒绝后停止自动重连，用户可显式重试。

浏览器 sessionStorage 仅保存随机令牌，序号与文档身份留在内存；Web Locks 防止复制页签继承接管令牌。刷新遇到旧 TCP 尚未关闭时，同身份有界重试 5 秒。服务端握手返回保留的发送元数据和事件，前端按原顺序重建本轮，不把缓存当作完整历史；回合结束后可重新读取原生记录。恢复失败不补发原输入，服务停止清空缓存并中断所属运行器。

原生存储是会话的唯一事实来源。列表在首次挂载时读取；新会话返回 id、回合结束、重命名、分支、归档、恢复或删除后，取消同 CLI 的在途摘要请求并使相关列表失效，避免首次加载中的旧结果覆盖新状态。项目变更仍重新计算全部摘要归属。没有目录监听、revision 轮询或会话刷新接口；重新打开应用会读取 CLI 已保存的记录，工作台不维护第二份正文。

### 4.5 附件缓存与媒体读取

附件缓存保存独立上传资产及归属元数据，不复制原生会话正文。上传内容与元数据分目录保存；上传、删除与回收串行化，首次会话归属通过单个有界清单原子提交。原生输入受理时取得租约，原生ID返回后先占用会话、完成绑定再发布事件，结束时释放。未经自持久证据确认的文件保持引用；服务器重启只恢复资产元数据和容量，不重新认领已失效页面的草稿身份。细化预算、三CLI转换及原生回放边界见[图片与媒体](native-dialogue.md#图片文件与媒体回放)。

## 5. 存储与配置

### 5.1 工作台数据

默认目录为 `%LOCALAPPDATA%\AgentDeck`，可由 `AGENTDECK_CONFIG_DIR` 指定。非 Windows 的默认位置回退到用户 `.local/share`。项目、服务器档案、产品偏好、加密凭据、插件注册与安装副本、启动环境均属于工作台数据；CLI 原生会话及配置保持原位置。

启动从生效配置目录读取当前格式的记录。项目结构为 `{ id, name, dir }`；缺文件时使用空列表，格式损坏时保留原文件并报错。

产品偏好保存默认 CLI、输入框光影开关、各 CLI 模型显示范围和旧资源工具参数；退休字段在磁盘读取边界定点剔除，公开写入仍严格校验。坏配置保留并返回错误，不用空对象掩盖损坏。

### 5.2 原生配置

资源目录由各 CLI 的已知文件和有界扫描生成，浏览器只提交服务端资源 id 和可选项目 id，不提交任意绝对路径。Claude 区分用户、共享项目与个人项目；Codex 配置、规则、共享 Skills 保留各自位置；Antigravity 不补造项目 settings。具体入口见[原生配置说明](native-configuration.md)。

`safe-file.ts` 逐层核对目录和文件身份；内容按 UTF-8 读取，revision 使用 SHA-256，同目录原子替换前再次校验。JSON/TOML 检查语法，其余规则原文留给 CLI 解释。目录 GET 只返回元数据，显式 POST open 才读取完整正文，保存响应不回显内容；旧两文件接口与资源接口共用按路径串行队列。扫描、文件大小与创建约束由原生配置说明维护，当前没有自动备份目录。

`session-preferences.json` 按 agent 与原生会话 id 保存归档标记和显式权限选择，不复制标题或正文。读写共用文件身份检查和路径事务；坏索引不覆盖。列表在原生枚举后按标记过滤，恢复撤销标记；已归档会话拒绝从旧选择继续发送或创建分支。原生删除成功后清理本地标记，附属清理失败不将已完成删除误报成失败。

启动环境对每种 CLI 单独限定变量，所有显式值使用系统加密，不修改本机服务的全局 `process.env`。新运行器持有启动快照；CLI 环境变量页单独保存后，已有实例仍保留快照，显式重启在空闲时释放运行器。模型与连接表单保存会自动完成这次回收，两种路径都在后续发送时重新启动。状态响应不包含旧值；密钥由小眼睛触发独立读取，明文仅驻留当前查看控件，原生文件编辑器也仅在显式打开期间持有正文。

模型设置接口提供白名单字段表单，与原文编辑复用同一资源服务。保存后撤销对应 CLI 的能力缓存和在途发现；前端查询取消与刷新代次共同防止旧结果回填。字段映射、认证保护、TOML 定点编辑和密钥存储区别集中记录在配置说明中。

### 5.3 启动配置

| 变量或参数 | 用途 |
|---|---|
| `AGENTDECK_HOST`、`AGENTDECK_PORT` | 本机监听，默认 `127.0.0.1:4317`；端口可用 0 申请系统分配 |
| `AGENTDECK_CONFIG_DIR` | 工作台配置目录 |

## 6. HTTP、安全与桌面生命周期

启动拒绝非回环 host。前端先调用 `POST /api/local-session`，校验本机 Host、精确允许的 Origin 与 Fetch Metadata 后获得 `AGENTDECK_session` Cookie；HttpOnly、SameSite=Strict，秘密比较使用常量时间。业务组件在握手成功后才挂载，握手等待上限 10 秒。

API 和 WebSocket 继续校验会话及来源；主应用禁止被 iframe 嵌入，开发来源必须显式放行。外部插件页面运行在无同源权限的受控 iframe 中，不能继承这些会话权限。普通 HTTP body 与对话 WS 上限为 1 MiB；原生文件等有独立预算的路由显式覆盖限制。日志只输出必要状态与版本，诊断避免携带完整配置或凭据。

| 接口域 | 当前路径与作用 |
|---|---|
| 项目 | `/api/projects` 与 `/:id`，列表/新增/修改/移除 |
| 会话 | `/api/projects/:id/sessions` 与 `/:agent/:sessionId`，原生读取；`/api/sessions?agent=...` 发现无归属摘要 |
| 主会话历史页 | `/api/projects/:id/sessions/:agent/:sessionId/history-page`，适用于 Codex 和 AGY，使用可选 `before` 继续读取更早的原生记录 |
| 原生管理 | `/api/projects/:id/sessions/:agent/:sessionId/actions`、`/fork`，来源及项目均在路径中 |
| 探测与能力 | `/api/agents/probes`；项目下 `agent-capabilities` 缓存与显式刷新 |
| 设置 | `/api/settings/product`、`/environment`、`/launch-environment/:agent`，原生文件由 `/api/native-resources/:agent` 提供 |
| 模型设置 | `/api/settings/models/:agent` 读取与保存表单；`/catalog` 的 GET 只读缓存，POST 原生获取，工作目录由可选 projectId 解析；`/context-window` 只读 AGY 当前模型窗口，可选 model 使用启动选择器相同的身份 |
| 官方额度 | AGY：`POST /api/settings/models/antigravity/official-usage`；Codex：`POST /api/workspaces/:id/codex/official-usage`，有会话时可传 `sessionId` 校验归属并使用原生目录。均为用户显式查询，不写入缓存 |
| 插件 | `/api/plugins/*`，安装注册、启停、静态页面与权限内的设置存储 |
| 对话 | `/ws`，恢复握手/有序补收、发送、停止、审批答复及回合事件 |
| CLI 维护 | `/api/settings/cli-installation/:agent` 读取本机状态，`/check` 查新，`/operations` 安装、更新或修复。详见[程序版本管理](native-configuration.md#cli-程序版本管理) |
| 会话引用工具 | `/api/session-tools/:agent`，只读 MCP 的登记状态、启停与原生配置事务 |
| SSH 档案 | `/api/ssh-targets`、`/api/ssh/*`，档案、认证、信任 |
| SSH Console | `/api/ssh-console/:serverId/*`，alias 定位概览、进程、作业、只读文件和终端 |

会话正文和管理只使用项目路径，全局发现不提供正文或写入入口；`/api/sessions/archived?agent=...` 汇总各来源的归档，恢复和删除仍走项目身份校验；旧工作区会话别名返回 404。会话接口在进入解析前设置 no-store，写入确认和原生会话锁仍由服务层维护。前端构建由 Fastify 托管，接口路径不回退为 HTML。

安装版与静态预览的 Electron 主进程用端口 0 启动服务后加载实际地址；preload 仅暴露受校验的系统信息、目录选择、打开路径、菜单和会话链接桥，`nodeIntegration: false`、`contextIsolation: true`。单实例锁让第二次启动聚焦已有窗口，关窗和退出都先释放服务，最长关闭等待 8 秒。后端清理终端、SSH、轮次和 HTTP；进程退出不留下后台业务实例。

桌面开发通过 Vite 加载源码页面，后端使用固定端口接受同源代理。React/CSS 采用热更新，preload 重建触发整页刷新，主进程及后端源码重建触发应用重启；这是开发工作流，不提供在途模型任务无中断迁移。开发监听范围和使用方式见[开发指南](../guides/dev-environment.md#3-启动与隔离验证)。

桌面后端与启动诊断通过专用 Console 输出；stdout/stderr 的异步 EPIPE 单独处理，接收日志的终端退出不再触发主进程错误弹窗。其他流异常继续抛出，业务异常仍由原启动失败与窗口流程报告，不安装全局异常吞错处理器。

## 7. SSH 基础与控制台约束

档案、信任和凭据由内置 SSH Console 使用，控制台以服务器 alias 定位目标，与本地项目独立。

### 7.1 档案、连接与凭据

服务器档案最多 128 条，hostname+端口+账号去重，alias 为产品生成的稳定 id。连接只接受 `{ alias }`，目标与认证材料来自档案；修改和移除在 revision/expected 快照上比较，被其他操作抢先时返回 409。`~/.ssh/config` 当前仅显式导入，未支持选项保留提示，不自动改写。

连接按真实身份与认证材料、信任记录复用。断开、改凭据或重连增加认证代次，迟到结果不能回填新身份；exec、SFTP 和 PTY 独立通道，单通道错误只释放自己。

未知主机先做不带凭据的握手，返回 SHA256 指纹和一次性挑战；挑战有效 2 分钟，最多 32 个，确认后记入 known_hosts。变更或吊销主机直接拒绝。密码仅内存或 Windows 当前用户 DPAPI 密文，编辑时按需读取并 `no-store`；凭据目录/文件保持相应访问权限。加密子进程使用环境白名单、stdin 传值，10 秒超时。

### 7.2 终端

终端按服务器与目录打开，不再生成绑定项目的票据；控制台租约记录 alias、连接代次与缓存键，打开与读写前后各复核一次，旧连接的结果不会流进新代次界面。当前每台服务器最多 6 个终端会话、全局 32 个，单标签最多 4 个窗格。

终端独立升级通道复用 HTTP 服务，base64 输入单帧 32 KiB，控制帧 64 KiB，输出缓冲 1 MiB。输入输出分别背压，排空后报告退出；EOF 不是可靠退出码，未知退出码保持 null。

xterm 实例与布局槽位分离，切视图或收起不销毁 PTY；关闭窗格才结束对应 shell，多行粘贴先确认。断线保留输出并停止输入，新连接创建新 shell，不宣称恢复原进程。

### 7.3 资源、进程与作业

控制台每 2 秒刷新、采样超时 25 秒；进程页取前 100 项系统进程、最多 512 条 GPU 进程。只在页面与该服务器可见、连接就绪时请求，隐藏立即取消在途采样。命令使用 `/proc`、`df`、`ps` 与 `nvidia-smi` 等只读接口，不安装采集器。缺值为 null，失败保留最近值并标过期；成功保留 5 秒，失败指数退避不超过 30 秒，空闲 60 秒淘汰。

Slurm 单一路径为 `LC_ALL=C squeue --noheader --user="$(id -un)" --format=...`。总预算 8 秒，合计输出上限 512 KiB，最多 200 行；未安装（127）、空输出、失败分别处理。仅首次或手动查询，不管理作业、不轮询调度器；成功缓存 2 秒，最多 32 项，认证变化取消查询并清理旧缓存。输出按原生列宽原样显示，前端不二次拆列。

三条只读命令共用 `console/command.ts`：通道归本次调用所有，结束、取消或超时只关这条通道，不碰共享连接。

### 7.4 只读文件浏览

目录浏览与预览只使用 SFTP，按服务器定位，不携带项目身份。单层最多 400 项，预览取开头最多 256 KiB，超出部分明确标注截断。只浏览元数据与常规文本，不提供新建、移动、删除、上传或下载，也不向本机落盘。

## 8. 工作台插件与独立控制台

插件注册表与自身设置采用 revision 校验。外部静态包复制入工作台目录，安装不执行脚本；启用后只可通过声明权限访问自己的 JSON 设置、当前项目摘要和命令通知。页面校验入口摘要，sandbox 不给予同源、任意网络或 Node 权限；关闭页面与停用/卸载各有独立处理。详细配额和消息边界见[工作台插件接口](workbench-plugins.md)。

SSH Console 只以服务器 alias 定位，不伪造 Workspace：服务器档案独立于项目，projects 里没有 `server`/`remoteDir`，也没有项目引用锁定。overview、processes、jobs 只对当前可见目标请求；只读文件使用 SFTP。作业页用 `console/jobs/slurm.ts` 查询当前登录账号的 `squeue`，与 overview/processes 共用 `console/command.ts` 的租约通道与 `console/monitoring/cache.ts` 的代次缓存。后端 PTY registry 保存通道和有界输出，HTTP 读返回 base64 原始字节与 `nextSeq`，前端消费后才推进游标；读取被裁剪的旧区间时明确 reset。隐藏暂停浏览器读取但不结束 shell，重新打开先取终端列表；关闭单终端才释放其通道。

停用插件会结束控制台内终端并释放页面状态，重新启用从空列表开始；服务器档案、凭据密文、项目与共享连接保留。

xterm 按需加载，复制、粘贴和回滚查找在当前窗格内执行；输出字节直接写入，避免逐块 UTF-8 解码损坏字符。查找依赖 SearchAddon，不向服务器发送命令。插件页面关闭时 SSH 页面保持挂载并暂停观察，外部 iframe 则卸载。

## 9. 本地打包与验证

electron-builder 定义 Windows x64 NSIS 和 portable 目标，默认禁止签名和发布。桌面主进程及业务依赖随包提供，静态前端置于 resources/web；用户 CLI、原生认证及工作台数据不打入程序。包内路径按 `process.resourcesPath` 解析，程序安装位置与配置目录分离。构建和卸载规则详见[本地安装指南](../guides/local-installation.md)。

模块行为、受控进程、浏览器、包内启动与真实外部链路分别验证，结果统一记录在路线图。
