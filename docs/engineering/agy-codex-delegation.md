# AGY 委派 Codex

更新日期：2026-11-26。接入基线为 AGY 1.5.14、Codex 0.170.0。独立插件与宿主接续接口已实现。通过 AgentDeck 使用官方登录 AGY 和真实 Codex，在临时项目完成两轮文件修改、同会话返修、原生审批往返、重开后自动验收及删除联动；原生固定响应对照也已通过。安装交付状态见[路线图](../roadmap.md)。

## 结论

目标是用户与 AGY 交流，在明确允许后由 AGY 把任务交给 Codex，接收问题与结果，并在同一个 Codex 会话中返修。产品交付为 AgentDeck 的独立可选工作台扩展，源码归入 agentdeck-plugins 仓库。

AGY 官方插件支持 Skill、本机工具和 Hooks，可用作原生 CLI 的接入层；本机 `agy plugin --help` 列出 install、enable、disable、validate。它与 AgentDeck 工作台插件使用不同接口和清单，不能把两种插件包混用。[插件格式](https://antigravity.google/docs/build-plugins/)

Codex app-server 提供原生 thread/turn、续接、追加输入、中断与提问协议；本仓库已有对应运行器和交互适配。本机导出的协议同时确认 threadId、turnId、model、effort 和终态字段，可沿用当前 Codex 连接与认证。[App Server](https://learn.chatgpt.com/docs/app-server)

插件在独立进程中维护任务身份和原生执行连接。AGY 使用原生 Hook 绑定会话来源，通过 MCP 工具控制委派，工作台提供配置、任务列表与会话接续。

## 显式授权入口

默认 AGY 按原来的方式处理任务，不自动发起 Codex 委派。启用扩展只让功能可用；用户在发送消息时使用以下入口，才授予本次任务的委派权限：

```text
/with-codex 修复这个问题并检查结果
```

`/with-codex` 由插件 Hook 识别。终端可能将它展开为插件具名 Skill，接入层同时识别两种形式。AGY 收到任务正文后，先澄清和拆分，再决定是否需要 Codex；允许委派不要求每次都创建 Codex 任务。

- 授权覆盖这次任务及后续补充、答复和返修，同一任务继续使用原授权和 Codex 会话。
- 后续无关的新任务恢复默认处理，需要再次使用 `/with-codex`。引用旧会话、读取文档或模型自行表达“可以委派”均不创建授权。
- 授权与原始用户消息、AGY 会话及任务绑定。创建委派时由执行端校验，不能仅凭模型提交的允许标志启动。
- 工作台与原生 AGY 接入层使用同一命令语义；命令交给接入层处理，AGY 执行任务正文，不切换当前对话的 CLI。

## 任务交互

| 操作 | 行为 |
|---|---|
| 创建任务 | 本次任务已有明确授权后，AGY 先澄清目标、范围、工作目录、必要材料与验收条件，再按需创建独立 Codex 会话；返回固定任务标识，重试不重复开工 |
| 查看与等待 | 按任务标识读取当前进度、增量结果或问题；一次等待有时限，到时返回当前状态 |
| 需要外部答复 | 缺少必要材料、要求存在实质冲突或需要新增人工授权时暂停执行，将阻塞交给 AGY；AGY 能根据已有要求处理时自行答复，需要用户取舍时在主对话询问 |
| 回答问题 | 答案回到同一任务和 Codex 会话，随后继续执行；普通澄清与原生权限请求分别按对应协议处理 |
| 继续与返修 | 沿用原 thread；需要新回合时新建 turn，只传 AGY 明确追加的要求 |
| 主动取消 | 发出原生 interrupt，并在确认原生终态后报告停止完成；保留已有会话记录 |
| 完成 | Codex 完成任务后收束本次执行，将原生结果交给 AGY 验收；需要返修时续接原会话 |
| 删除 AGY 会话 | 停止其仍在执行的委派，删除由它创建的 Codex 会话及关联记录；项目文件保留 |

AGY 不自动转发之后的全部聊天。Codex 的上下文来自原委派、明确补充材料和自己的原生执行记录。插件只保存任务身份、状态、配置和读取位置，不另存一份对话正文。

控制接口传递任务指令、问题、进度和结果摘要，详细执行记录保留在 Codex 原生会话。扩展启动原生 Codex 进程并转交消息，不接管模型 HTTP 请求。

模型、思考强度、执行权限与审批策略统一配置一次，不增加命名预设。初始沿用 Codex 当前生效配置，显式选择后由后续委派统一使用；每轮记录实际使用的参数，修改配置不改正在执行的任务。API 地址与凭据继续由 Codex 原生配置管理，保持现有 API 认证。

上述委派设置作用于主 Codex 会话。其原生子代理由 Codex 自己解析配置，沿用 `config.toml` 中 `[agents]` 的 `default_subagent_model` 和 `default_subagent_reasoning_effort` 等默认值；显式创建参数、自定义代理文件及未设置时的继承均服从原生优先级。插件不复制一套子代理设置，不把主会话的模型和强度强制覆盖到每个子代理，也不改写原生代理配置。[子代理配置](https://learn.chatgpt.com/docs/agent-configuration/subagents)

编译、测试或命令报错等任务范围内可排查的问题，由 Codex 继续诊断和修复，不逐项交给用户。原生执行失败按失败结果返回 AGY，任务需要外部答复时才进入暂停状态。

任务处于待答状态时结束当前工具等待，不继续调用 Codex 模型，也不高频轮询；保留原会话和待答信息，不用取消任务或清空上下文代替暂停。若原生审批必须保留请求连接，实现者负责管理空闲连接。回答沿有效原生请求送达；进程已退出时先核对原生状态，再沿同一会话恢复，不向失效请求补造批准。

## 生命周期与关联

- AGY 一轮回复结束或 CLI 退出，不结束仍在执行的 Codex 任务。执行端独立管理任务进程；正常任务完成后结束本次执行。
- AGY 仍打开时，后台等待工具返回会触发后续验收；最终回合结果在后台工作完成后发出。关闭后保留状态和原生记录位置：AgentDeck 重开原会话时发起接续，包括已读取但尚未验收的完成结果；已展示的待答问题不重复催问。独立终端恢复旧会话不会触发 Hook，用户发一句“继续”后再读取结果。
- 停用插件阻止新委派；已启动的任务继续到完成、需要答复、失败或主动取消。完成后释放执行资源，暂停任务保留接续所需状态。重新启用后沿原关联读取结果或恢复暂停任务，不自动重开任务。
- 工作台删除 AGY 会话前，先通知插件停止并清理所属委派；清理失败时保留原 AGY 会话。Codex 的原生删除负责清理登记的子代理后代。外部移除依据先前已确认存在的原生轨迹和脑目录核对，连续确认两者都消失后再清理；摘要库缺行或读取失败不作为删除依据。
- 每个委派绑定发起它的 AGY 原生会话、任务标识与 Codex thread。AGY 原生 Hooks 的公共字段提供 `conversationId`；工作台与独立 CLI 均需验证真实传递，不由模型猜测归属。[Hooks](https://antigravity.google/docs/hooks/)

## 工程默认值

这些属于实现职责，按下列约束落实并验证：

- 独立任务新建 Codex 会话，同一任务的补充与返修沿用原会话。任务之间不混入后续全部 AGY 聊天。
- 同一工作目录的独立委派按顺序执行；隔离目录的任务可并行。AGY 交付委派期间避免修改相同任务范围，验收基于 Codex 实际结果。
- Codex 内部拆分优先沿用其原生子代理能力，遵守原生配置及仓库对委派的要求；插件不另建一套子代理框架或配置。[Codex 子代理](https://learn.chatgpt.com/docs/agent-configuration/subagents)
- 工具超时或断线先查询原任务状态，不把通信失败当作执行失败。任务身份与提交记录在启动前持久化，重复调用返回同一任务。
- 崩溃或重启后核对原生进程与线程状态，恢复原任务的关联和读取位置；核对已产生的修改后继续剩余工作，不从头重放整份任务。
- 模型、权限、关联来源和生命周期按原生证据验证；必要的技术取舍由实现者处理，只在需要用户做业务取舍时回到 AGY 主对话。

## 插件归属、开关与接入方式

AgentDeck 扩展提供管理、配置及消息授权入口，AGY 侧负责接入命令、原生会话身份与任务控制工具。独立 AGY CLI 与工作台复用同一执行端和委派配置，扩展关闭后不创建新委派；已有任务按前述生命周期收束。

工作台插件后端随应用退出而停止；委派执行端通过本机管道独立运行，持有原生 Codex 连接。宿主新增的会话控制权限与删除前通知是通用扩展接口，业务实现留在插件仓库；接口见[工作台插件](workbench-plugins.md)。

原生插件提供创建、等待、读取、答复、续接、取消、验收和结束授权的 MCP 工具。Hook 校验用户入口和会话来源，Skill 说明协作流程；它与读取历史用的会话引用接口无关。用户在插件页点击「连接并允许委派」，安装原生接入并允许该插件的工具，已有明确拒绝或询问规则不被覆盖。卸载只移除本插件新增的规则；不预装进 AgentDeck。

等待使用 AGY 的后台工具机制，每次有界等待返回原任务状态；需要外部答复时立即结束等待。插件不把等待超时当作执行失败。[工具调用与时限](https://antigravity.google/docs/mcp/)

## 原型与实现验收

- AGY 正常委派，Codex 使用统一配置执行，结果回到发起任务的调用。
- 普通消息不创建 Codex 任务；`/with-codex` 只授权本次任务及返修，新任务和其他会话不能沿用。
- 主 Codex 设置与原生子代理默认值分别生效，插件不额外覆盖子代理模型、强度或权限继承。
- 缺材料或出现审批时，任务暂停、问题返回 AGY，答案能送达原任务，等待期间不继续调用 Codex 模型。
- 返修延续原 thread；另一个 AGY 会话的任务、问题和结果不会串入。
- 等待超时与工具重试不重复执行；取消与迟到完成不会覆盖新一轮。
- 原生 Hooks 与工作台分别确认发起会话身份，独立 CLI 与官方登录入口使用相同委派配置。
- AGY 回复结束、CLI 退出和停用插件后，已有 Codex 任务按上述生命周期继续并能取回结果；取消或删除所属 AGY 会话时能终止对应任务。
- 工作台删除与外部删除分别验证关联清理；只删除所属委派会话和原生后代，项目文件保留。
- 配置修改与服务崩溃分别验证；恢复沿原任务核对，不自动重复已执行的工作。
- 既有 Codex API 连接保持当前配置，真实模型闭环使用单独约定的验证范围。

原生探针采用隔离配置与本机固定响应，已核对 Hook 原始输入、会话绑定、MCP 参数改写、后台结果唤醒及旧会话恢复边界。受控 Codex 子进程验证请求生命周期和任务状态，不代表真实模型、真实审批或所有子代理组合已经验收。

两套真实 CLI 的本机固定响应验证覆盖创建、后台等待、同一 Codex 会话返修、验收和结束授权；分别验证显式模型参数与原生默认值。工作台界面已核对四行平铺设置、原生模型与强度、保存、深浅主题和键盘操作。

官方账号真实验收中，AGY 指挥 Codex 将临时文件依次修改为两份约定内容，两轮使用同一个 task 和 thread。Codex 沿用原生模型、强度、只读沙箱及按需审批，写入审批通过 AGY 往返；AGY 读取文件后确认验收并结束授权。第二轮完成后退出验收回合，重开原会话自动继续验收。随后通过工作台删除该测试会话，原生 AGY 记录、关联 Codex 记录及插件任务均移除，项目文件保留。

真实验收修复了短命令转交、首次工具权限入口、已读未验收结果的重开接续，以及 Windows 目录别名与删除成功响应。快速关闭重开另由宿主打开标识和页面恢复测试覆盖。开始阶段曾遇到官方账号检查连接中断，恢复网络后才进入委派；不计为委派成功。真实子代理后代删除与执行中取消仍仅有受控协议证据，本次真实任务没有创建子代理。

2026-11-26 补充：原生 `thread/delete` 已移除测试会话及记录，但当时运行的 Codex 桌面端在自身持久化聊天目录保留了失效条目，重启后仍显示，再次删除返回“找不到原生记录”。核对精确会话身份后单独清理该目录条目，原生删除验收不等于所有外部客户端的列表同步通过。插件不直接改写 Codex 桌面端的私有目录数据库。
