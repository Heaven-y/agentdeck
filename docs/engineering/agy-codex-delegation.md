# AGY 委派 Codex：可行性与实现范围

核对日期：2026-11-23。本机版本为 AGY 1.5.14、Codex 0.170.0。本轮完成协议与插件格式调研，尚未实现或启用委派插件，没有发送真实模型任务。

## 结论

可以实现用户与 AGY 交流、AGY 把明确任务交给 Codex、接收问题与结果、在同一个 Codex 会话中返修的完整交互流程。建议作为独立可选扩展管理，源码归入独立的 agentdeck-plugins 仓库。

AGY 官方插件支持组合 Skill 和本机工具，提供配置变量、持久插件数据目录以及启用/停用入口；本机 `agy plugin --help` 也列出 install、enable、disable、validate。配置变量可在 `/plugin` 中设置，适合一次填写委派使用的模型、强度与权限。[插件格式](https://antigravity.google/docs/build-plugins/)

Codex app-server 提供原生 thread/turn、续接、追加输入、中断与提问协议；本仓库已有对应运行器和交互适配。本机导出的协议同时确认 threadId、turnId、model、effort 和终态字段，可沿用当前 Codex 连接与认证。[App Server](https://learn.chatgpt.com/docs/app-server)

以上支持交互式委派闭环。AGY 会话结束后的自动唤醒、关闭 CLI 后继续执行、重启后接管仍在执行的进程，需要另外实现并验证，不能从线程可续接推导出来。

## 建议的功能契约

| 操作 | 行为 |
|---|---|
| 创建任务 | AGY 明确提交目标、工作目录、必要材料与验收条件；返回固定任务标识，重试不重复开工 |
| 查看与等待 | 按任务标识读取当前进度、增量结果或问题；一次等待有时限，到时返回当前状态 |
| 回答问题 | 将明确答案交还对应的 Codex 原生请求；权限审批与普通澄清分别处理 |
| 继续与返修 | 沿用原 thread，新建后续 turn；只传 AGY 明确追加的要求 |
| 停止 | 发出原生 interrupt，并在确认原生终态后报告停止完成 |
| 完成 | 结果与对应任务、thread、turn 绑定；AGY 按原验收条件检查实际修改，再向用户交付 |

AGY 不自动转发之后的全部聊天。Codex 的上下文来自原委派、明确补充材料和自己的原生执行记录。插件只保存任务身份、状态、配置和读取位置，不另存一份对话正文。

控制接口传递任务指令、问题、进度和结果摘要，详细执行记录保留在 Codex 原生会话。扩展启动原生 Codex 进程并转交消息，不接管模型 HTTP 请求。

模型、思考强度和执行权限统一配置一次，不增加命名预设。每轮启动记录所用参数；修改配置只影响后续执行。API 地址与凭据继续由 Codex 原生配置管理，插件不接管认证。

## 开关与接入方式

建议优先使用 AGY 原生插件，独立 CLI 与工作台中的 AGY 共用同一个用户级配置和开关。未启用时不启动委派服务，也不增加 AGY 可用工具。停用前需要处理正在执行的任务，避免遗弃 Codex 进程。

原生插件内可用 MCP 暴露有状态的任务操作；这与已经删除的“会话引用 MCP”是两个用途。也可用 Skill 调用本机命令，但进度、提问、取消和同一任务续接仍需要一个明确的控制接口。上述入口选择是实现建议，并非本轮已经安装的功能。

AGY 文档给出的默认工具调用时限为 180 秒，连接时限为 300 秒；因此一次工具调用不宜一直阻塞到长任务结束。`start/wait/answer/continue/cancel` 是建议的扩展接口，不冒充 AGY 原生命令。官方的 background 设置尚不足以证明结果能在已结束的 AGY 会话中自动回投。[工具调用与时限](https://antigravity.google/docs/mcp/)

## 实现前必须覆盖的验收

- AGY 正常委派，Codex 使用统一配置执行，结果回到发起任务的调用。
- 缺材料或出现审批时，问题能返回、答案能送达，双方不会相互等待。
- 返修延续原 thread；另一个 AGY 会话的任务、问题和结果不会串入。
- 等待超时与工具重试不重复执行；取消与迟到完成不会覆盖新一轮。
- 配置修改、停用、CLI 退出和服务崩溃分别验证；重启只恢复可证明的状态。
- 既有 Codex API 连接保持当前配置，真实模型闭环使用单独约定的验证范围。

本机已核对现有协议 schema 与原生插件命令；此前留存的插件格式验证只证明清单可被接受。任务往返、原生审批以及服务退出时的完整行为仍需要实现后的联调。
